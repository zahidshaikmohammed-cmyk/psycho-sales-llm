## 2. The ten permanent phases

### Phase 1 — Constitution and Quality Standard
Apply and verify the permanent Knowledge Object Constitution, including semantic completeness, conceptual distinction, mechanism integrity, evidence/uncertainty, ownership, relationships, retrieval, anti-template controls, scientific boundaries, and machine composability.

### Phase 2 — Validation Infrastructure
Maintain executable structural validation and mandatory semantic attestation so a chapter cannot be sealed from section-counting alone.

### Phase 3 — Semantic Remediation
Deepen every chapter until each Topic contains the knowledge genuinely required by its subject matter, without artificial length or duplicated ownership.

### Phase 4 — Conceptual Distinction
Audit nearest-neighbor concepts and prevent retrieval or human understanding from collapsing distinct constructs, processes, mechanisms, states, phenomena, models, or clinical conditions.

### Phase 5 — Scientific and Evidence Integrity
Separate definitions, empirical findings, associations, causal evidence, theories/models, interpretations, contested findings, and unresolved questions. Preserve uncertainty where it matters.

### Phase 6 — Ownership and Cross-Chapter Boundaries
Apply the precision registry globally. Enforce one canonical owner per construct/mechanism/etc.; classify relationship/application nodes, duplicate aliases, redirects, and theory/model objects correctly.

### Phase 7 — Retrieval and Machine Composability
Ensure natural-language retrieval variants, explicit relationships, ownership metadata, boundaries, evidence status, and useful semantic hooks support precise downstream machine retrieval.

### Phase 8 — Knowledge Graph Integration
Integrate validated chapter Knowledge Objects into the derived graph using typed relationships. Do not fabricate unsupported causal or mechanistic edges.

### Phase 9 — Repository Synchronization
Reconcile chapter state, validation records, precision metadata, remediation register, graph state, roadmap, and README against the live repository.

### Phase 10 — Final Encyclopedia Certification
Perform a project-wide final audit across all 21 chapters, architecture, ownership accounting, validation records, graph integrity, retrieval controls, and metadata. Only then may the encyclopedia be declared complete.

## 3. Chapter execution rule

Every chapter must pass the relevant gates before it can be marked **LOCKED & SEALED**.

A chapter is not complete merely because it has six sections per Topic.

Minimum chapter completion requires:

1. exact architecture match;
2. correct ownership classification;
3. semantic completeness appropriate to each Topic;
4. neighboring-concept distinction;
5. scientific/evidence integrity;
6. meaningful boundaries and deferrals;
7. retrieval robustness;
8. anti-template validation;
9. graph integration or explicit graph disposition;
10. final validation record.
